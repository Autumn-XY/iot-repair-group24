# 需求说明

## 角色与范围
报修人：负责查看设备信息、对故障设备提交报修，形成初始状态为 PENDING 的工单。
维修人员：负责查看设备信息，并对已有工单推进状态：将 PENDING 工单转为 PROCESSING（开始处理），将 PROCESSING 工单转为 COMPLETED（处理完成）。
范围：本实验只实现工单状态判断函数，不实现完整的设备管理、报修提交与工单存储功能；FR-01、FR-02 作为需求说明保留，用于界定角色职责与业务背景，验收聚焦于 FR-03 状态判断函数的返回值与状态不变性。

## FR-01 查看设备信息
角色：查看人（报修人/维修人员）
前提：系统已内置模拟设备清单
行为与正常结果：查看人打开设备清单，系统显示每台设备的编号、名称、位置和当前状态（如正常/故障）；选择某台设备可查看其详细信息
异常结果：设备清单为空时提示"暂无设备信息"，不显示空白列表；所选设备不存在时提示"设备不存在"，不展示详情
验收方法：打开设备清单，检查是否列出全部模拟设备及其编号、名称、位置、状态；对DEV-001查看详情，核对显示字段与清单一致；请求不存在的设备编号，检查是否提示"设备不存在"

## FR-02 提交报修
角色：报修人
前提与输入：设备已列入模拟设备清单，选择设备，填写非空故障描述
正常结果：形成一张工单，记录设备编号和故障描述，工单初始状态为PENDING
异常结果：未选择设备或描述为空时提示补充，不创建工单
验收方法：对DEV-001提交"传感器没有读数"，检查设备编号、描述和初始状态是否符合要求

## FR-03 更新工单状态
角色：维修人员
允许的转换：PENDING → PROCESSING；PROCESSING → COMPLETED
拒绝的转换：PENDING → COMPLETED（未开始处理不得直接完成）；PROCESSING → PENDING（不允许回退）；COMPLETED → 任何状态（已完成工单不可再变更）；PENDING → PENDING、PROCESSING → PROCESSING、COMPLETED → COMPLETED（目标状态与当前状态相同，视为非法转换）；对不存在的工单编号执行更新
正常与异常结果：允许的转换返回成功，工单状态更新为目标状态；拒绝的转换返回失败并提示"不允许的状态转换"，工单状态保持不变；工单不存在时返回失败并提示"工单不存在"，不做任何更新
验收方法：对PENDING工单请求→PROCESSING，检查返回成功且状态为PROCESSING；对PROCESSING工单请求→COMPLETED，检查返回成功且状态为COMPLETED；对PENDING工单请求→COMPLETED、对PROCESSING工单请求→PENDING、对COMPLETED工单请求→任意状态、以及请求与当前状态相同的转换，检查均返回失败且状态不变；对不存在的工单编号请求更新，检查提示"工单不存在"且无状态变化

## 已确认的实验规则
新工单为PENDING，仅允许PENDING转PROCESSING、PROCESSING转COMPLETED。
其他转换一律拒绝。本实验暂不实现完整报修系统，只实现状态判断函数。
